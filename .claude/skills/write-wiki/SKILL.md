# write-wiki

용어 위키에 항목을 등록한다. 저장 구조는 다음과 같다.

```
terms/<category>/<keyword>/
  README.md        # 설명(explanation). 템플릿 고정
  reference/*.md   # 원문·스펙·출처. README 목록은 스크립트가 자동 갱신
```

- 템플릿: `.claude/skills/write-wiki/references/template.md`
- 작성 원칙: `.claude/skills/write-wiki/references/style-guide.md`
- 동기화/검사 스크립트: `.claude/skills/write-wiki/scripts/sync-references.mjs`

시작 전에 위 템플릿 파일을 읽는다.

## 0단계: 입력 라우팅 (가장 먼저)

입력을 아래 셋 중 하나로 분류한다.

| 유형 | 신호 | 처리 |
| --- | --- | --- |
| **A. 조사 결과 붙여넣기** | 설명문, 정의, 예시, 링크가 담긴 긴 글. 다른 에이전트의 답변 흔적(머리말·이모지·"도움이 되길") | 1단계(A 경로) |
| **B. 모르는 용어 질문** | 짧은 키워드, "~가 뭐야", "~ 조사해서 등록해줘" | 1단계(B 경로) |
| **C. 판단 불가** | 키워드 + 짧은 문장 정도로 어느 쪽인지 애매 | 한 가지만 질문: "붙여넣은 내용을 그대로 등록할까요, 새로 조사할까요?" |

A 로 분류해도 아래 중 하나면 B 경로를 병행한다 (신뢰할 수 없는 붙여넣기).

- 출처가 하나도 없고 버전·수치·날짜 같은 검증 가능한 주장이 있다
- 내용이 스스로 모순되거나 용어 설명이 아닌 잡담이다

## 1단계: 내용 확보

**A 경로**: 붙여넣은 글 전체를 원문으로 보존해 둔다 (4단계에서 reference 로 저장). 내용에서 키워드, 별칭, 출처 URL 을 뽑는다.

**B 경로 (새 조사)**: `research-term` 스킬을 호출해 보고서를 받는다. 키워드와 사용자가 준 맥락을 넘긴다. 받은 보고서의 "출처" 표와 "미확인·충돌"을 이후 단계에서 그대로 쓴다.

## 2단계: 위치 결정

1. 키워드 slug: 소문자 kebab-case 영문 (`prompt-caching`). 한글 용어도 영문 slug, 한글 표기는 `aliases` 에 둔다.
2. 카테고리: 기본 `development`, `video-generate`, `image-generate`, `legal`, `research`, `data-analysis`. `terms/` 에 이미 있는 폴더도 후보다. 내용에 맞는 게 하나로 분명하면 그것을 쓰고, 기존 카테고리에 맞지 않으면 새 카테고리를 제안해 사용자 확인을 받는다 (임의 생성 금지).
3. 중복 확인: `terms/*/<slug>` 와 `aliases` 를 grep 한다. 이미 있으면 새로 만들지 않고, 사용자에게 "갱신 / 병합 / 취소" 중 하나를 묻는다.

## 3단계: 연관 용어 탐색 (prev / next 결정)

기존 용어와 엮어 "먼저 알면 좋은 개념 → 이 용어 → 이어서 볼 개념" 흐름을 만든다. 링크드 리스트를 여러 갈래로 확장한 구조라 앞·뒤가 각각 여럿일 수 있다.

1. **후보 수집**: `terms/*/*/README.md` 의 front matter(`title`, `aliases`, `prev`, `next`)와 정의 인용문(`> `)을 훑는다. 새 용어의 키워드·별칭·본문에서 언급한 용어와 겹치는 것을 후보로 잡는다. 후보가 0개면 prev/next 는 비워 두고 `관련 용어` 에 `_(미확인)_` 을 적는다.
2. **방향 판정** (후보마다 하나로):
   - **prev**: 이 용어를 이해하려면 먼저 알아야 하는 개념. 정의·동작 설명에 그 용어가 전제로 쓰인다.
   - **next**: 이 용어를 알고 나면 자연스럽게 이어지는 심화·응용·후속 개념.
   - **인접(순서 없음)**: 비교·혼동 대상. prev/next 에 넣지 않고 `관련 용어` 본문에만 둔다.
   - **연결은 의무가 아니다.** "연결 없음"이 정상 결과다. 같은 카테고리이거나 이름·주제가 비슷하다는 이유만으로 잇지 않는다.
   - 연결하려면 두 문서 본문에서 근거를 짚을 수 있어야 한다. prev/next 는 한쪽 설명이 다른 쪽을 전제로 쓰거나 명시적으로 이어지는 경우만, 인접은 비교·혼동 지점이 본문에 있는 경우만 허용한다.
   - 선행 관계가 불분명하면 prev/next 로 올리지 않는다. 억지로 엮는 것보다 비워 두는 게 낫다. 순서는 없지만 관련은 있으면 인접으로 내린다.
   - 후보마다 근거 한 줄을 남긴다. 근거를 못 쓰면 제외한다.
3. **체인 정합성**: 새 용어를 넣은 뒤에도 기존 체인이 끊기지 않는지 본다. 이미 `A → C` 인 곳에 `B` 가 중간이면 A.next·C.prev 에 B 를 추가하되, 기존 A→C 직접 링크는 B 가 진짜 중간 단계일 때만 걷어낸다 (애매하면 둘 다 둔다).
4. **상대 용어도 갱신**: 새 용어의 prev 에 X 를 넣었다면 X 의 front matter `next` 에 새 용어를, next 에 Y 를 넣었다면 Y 의 `prev` 에 새 용어를 추가한다. 본문 `관련 용어` 에도 같은 링크를 한 줄 더한다. 이 수정은 링크 추가로 한정하고, 상대 문서의 다른 내용은 건드리지 않는다. 상대 문서의 `updated` 는 오늘 날짜로 바꾼다.
5. **사용자에게 보일 요약을 준비**: 후보별 판정(prev / next / 인접 / 제외)과 한 줄 이유. 5단계에서 보고한다.

## 4단계: 규격 변환

템플릿의 섹션 순서·제목을 그대로 사용해 README.md 를 쓴다.

- 붙여넣은 글의 어조·이모지·광고성 문구·"~해드릴게요" 같은 대화체는 제거하고 중립적 문어체로 정리한다.
- 정의는 `> ` 인용문 한두 문장. 내용에 없는 섹션을 지어내지 않는다. 필수 섹션(요약, 왜 필요한가, 어떻게 동작하나, 예시, 관련 용어, 참고 자료)에 쓸 근거가 없으면 `_(미확인)_` 으로 두고 사용자에게 알린다.
- 조사 보고서의 "미확인·충돌" 항목은 본문에 "미확인"으로 남긴다.
- 사용자가 붙여넣은 내용의 사실을 임의로 바꾸지 않는다. 틀려 보이면 바꾸지 말고 보고한다.
- `status`: 출처 대조를 하지 않은 붙여넣기와 C 등급만 있는 조사는 `draft`. A/B 출처 2곳 이상 대조된 경우만 `reviewed`.
- `updated`: 오늘 날짜.
- front matter 에 3단계에서 정한 `prev`, `next` (`category/slug` 목록)를 쓴다. 없으면 두 줄 모두 생략한다.
- `관련 용어` 는 `먼저 알면 좋은 용어(prev)` / `이어서 볼 용어(next)` / `비교·인접 용어` 로 나누고 링크 옆에 한 줄 관계 설명을 둔다. `terms/` 에 실제 존재하는 용어만 상대 경로로 건다.

## 5단계: 저장

1. `terms/<category>/<keyword>/README.md` 작성.
2. `terms/<category>/<keyword>/reference/` 에 파일 저장.
   - A 경로: 붙여넣은 원문을 `reference/original-notes.md` 로 보존 (상단에 "사용자 제공 원문, 조회·검증 전" 표기).
   - B 경로: 조사 보고서의 출처 표를 `reference/sources.md` 로 저장.
   - 상세 스펙이나 긴 예제가 있으면 주제별 `reference/<topic>.md` 로 분리. 파일 상단에 출처 URL 과 조회일.
3. 3단계에서 상대 용어를 고쳤다면 해당 파일도 저장한다.
4. 동기화 + 검사를 실행한다. prev/next 양방향 일치는 상대 용어까지 걸리므로 `--check` 는 경로 없이 전체로 한 번 더 돌린다.

```bash
node .claude/skills/write-wiki/scripts/sync-references.mjs terms/<category>/<keyword>
node .claude/skills/write-wiki/scripts/sync-references.mjs --check terms/<category>/<keyword>
node .claude/skills/write-wiki/scripts/sync-references.mjs --check
```

`--check` 가 FAIL 이면 고치고 다시 돌린다. 통과한 뒤에 다음 단계로 간다.

reference 파일을 나중에 직접 추가·삭제했을 때도 같은 동기화 명령을 실행하면 README 목록이 갱신된다.

## 6단계: 설명

저장 후 사용자에게 한국어로 보고한다.

1. 등록 위치(경로)와 선택한 카테고리·이유.
2. 용어를 3~5줄로 설명 (README 요약 기준).
3. 연결 결과: `prev → 이 용어 → next` 체인을 한 줄로 보이고, 함께 고친 상대 용어 파일을 나열한다.
4. 라우팅 결과 (붙여넣기 정리 / 새 조사) 와 `status`.
5. 미확인 항목, 원문과 달라진 부분, 새로 만든 카테고리가 있으면 명시.

커밋은 하지 않는다. 사용자가 요청할 때만 한다.
