# 데이터 누수 (Data Leakage)

> 예측 시점에는 알 수 없는 정보가 학습이나 평가 과정에 섞여 들어가, 평가 결과가 실제 성능보다 좋게 나오는 현상.

## 요약

- scikit-learn 문서는 데이터 누수를 예측 시점에 사용할 수 없는 정보를 쓰는 것으로 설명하며, 교차 검증 같은 추정치를 지나치게 낙관적으로 만든다고 한다.
- 크게 정답과 관련된 특징이 들어가는 경우(열 방향)와 표본 사이에서 정보가 공유되는 경우(행 방향)로 나뉜다.
- 기본 원칙은 분할을 먼저 하고, 전처리와 특징 선택을 훈련 데이터에서만 학습하는 것이다.
- [정확도](../accuracy/README.md)와 [F1 점수](../f1-score/README.md) 같은 평가 수치를 부풀리는 대표적인 원인이다.

## 왜 필요한가

검증 점수가 높아 배포했는데 실제 데이터에서는 성능이 크게 떨어지는 문제의 흔한 원인이 누수이다. 누수는 코드가 정상 동작하고 지표도 좋게 나오므로 오류로 드러나지 않는다. 원인과 유형을 알아야 평가 설계 단계에서 막을 수 있다.

## 어떻게 동작하나

위키백과는 누수를 두 유형으로 정리한다.

| 유형 | 설명 | 예 |
| --- | --- | --- |
| 특징 누수(열 방향) | 특징이 정답의 복사본이거나 대리 변수 | 연봉 예측에 월급 열 포함, 지각 여부 예측에 지각 시간 포함 |
| 표본 누수(행 방향) | 훈련과 평가 행 사이에 정보가 공유됨 | 분할 전 스케일링, 중복 행, 같은 환자 영상이 양쪽에 존재, 시계열 무작위 분할 |

훈련·검증 분리 원칙은 다음과 같다. scikit-learn 문서가 제시하는 내용이다.

1. 전처리보다 먼저 훈련 집합과 평가 집합으로 나눈다.
2. 평가 데이터에는 `fit` 이나 `fit_transform` 을 호출하지 않는다. 훈련 집합에서 `fit_transform` 을 하고 평가 집합에는 `transform` 만 적용한다.
3. `Pipeline` 을 사용하면 교차 검증 중에도 각 단계가 올바른 부분 집합에만 적용된다.

Kaufman 등의 KDD 2011 논문은 누수를 학습 대상에 대한 정보가 정당하게는 얻을 수 없는 곳에서 들어오는 것으로 정의하고, 학습과 예측을 분리하는 데이터 관리를 해법으로 제안한다. 이 논문은 검색 결과의 초록으로만 확인했다.

## 예시

scikit-learn 문서의 실험이다. 무작위 특징 1만 개와 무작위 이진 레이블이므로 기대 정확도는 약 0.5 이다.

```python
# 잘못된 방식: 전체 데이터로 특징 선택 후 분할
X_selected = SelectKBest(k=25).fit_transform(X, y)
X_train, X_test, y_train, y_test = train_test_split(X_selected, y, random_state=42)
# 정확도 0.76 (부풀려짐)

# 올바른 방식: 분할 후 훈련 집합에서만 선택
X_train, X_test, y_train, y_test = train_test_split(X, y, random_state=42)
select = SelectKBest(k=25)
X_train_sel = select.fit_transform(X_train, y_train)
X_test_sel = select.transform(X_test)
# 정확도 0.5 근처
```

무의미한 데이터에서 0.76 이 나오는 것은 모델이 학습한 것이 아니라 평가 데이터의 정답 정보가 선택 단계에 쓰였기 때문이다. 이런 평가에서는 정확도뿐 아니라 정밀도, 재현율, F1 도 함께 부풀려진다.

## 에이전트 맥락

코딩 에이전트가 만든 분석 코드에서 `StandardScaler().fit_transform(X)` 를 분할 전에 적용하거나, 평가 집합을 참고해 특징을 고르는 패턴이 있는지 점검할 만하다. 에이전트 코드에서 실제로 얼마나 자주 발생하는지는 조사하지 못했으며 미확인이다.

## 흔한 오해

- **누수는 정답 열을 실수로 넣는 경우만이 아니다.** 분할 전 전처리, 중복 행, 같은 환자·사용자가 양쪽에 나뉘는 경우, 시계열을 무작위로 섞는 경우도 누수이다.
- **지표가 높으면 모델이 좋은 것이 아니다.** 평가가 오염되었는지 먼저 의심해야 하며, 재현되는 높은 수치가 곧 올바른 수치는 아니다. [재현성](../reproducibility/README.md)과 별개의 문제이다.
- **교차 검증을 하면 안전하다는 생각은 틀리다.** 교차 검증 전에 전체 데이터로 전처리하면 누수가 생긴다. 파이프라인 안에서 교차 검증해야 한다.
- **누수와 과적합은 다르다.** 과적합은 훈련 데이터에 지나치게 맞는 것이고, 누수는 평가 자체가 오염되는 것이다. 이 구분은 이번 조사에서 별도 출처로 확인하지 못했다. 미확인.
