# BM25

> 질의 단어가 문서에 나타나는 빈도, 단어의 희소성, 문서 길이를 함께 반영해 문서의 관련도 점수를 매기는 확률적 검색 모델 기반의 순위 함수.

## 요약

- BM25 는 Okapi 시스템에서 처음 구현되어 Okapi BM25 라고도 부르며, 확률적 관련성 모델(probabilistic relevance model)에서 발전했다.
- 점수는 질의 단어별 기여의 합이다. 기여는 역문서 빈도(IDF), 단어 빈도(TF), 문서 길이 정규화로 정해진다.
- k1 은 단어 빈도가 점수에 미치는 영향의 포화 속도를, b 는 문서 길이 정규화의 강도를 조절한다.
- 단어 일치에 기반하므로 희소 검색(sparse retrieval)으로 분류된다.

## 왜 필요한가

단순히 질의 단어가 나온 횟수만 세면 긴 문서가 유리하고, 흔한 단어가 점수를 지배한다. BM25 는 흔한 단어의 가중치를 낮추고(IDF), 같은 단어의 반복이 주는 이득에 한계를 두며(TF 포화), 긴 문서에 불이익을 주어(길이 정규화) 이 문제를 줄인다.

## 어떻게 동작하나

Stanford IR 교재(Manning 등)가 제시하는 식은 다음과 같다.

```
RSV_d = Σ_{t in q} log(N / df_t) * ((k1 + 1) * tf_td) / (k1 * ((1 - b) + b * (L_d / L_ave)) + tf_td)
```

tf_td 는 문서 d 에서 단어 t 의 빈도, L_d 는 문서 길이, L_ave 는 컬렉션의 평균 문서 길이, N 은 문서 수, df_t 는 단어 t 를 포함한 문서 수이다. 구현체마다 IDF 항의 세부 형태는 다를 수 있다(Elastic 문서는 BM25 의 IDF 가 TF/IDF 의 것과 다르다고 설명한다).

| 매개변수 | 의미 | 극단값 | 흔한 기본값 |
| --- | --- | --- | --- |
| k1 | 단어 빈도 반영 정도(포화) | 0 이면 단어 빈도를 무시하고 이진 모델이 되며, 클수록 원 빈도에 가까워진다 | Elastic 1.2, 교재는 1.2 에서 2 사이를 합리적 범위로 제시 |
| b | 문서 길이 정규화 강도(0 에서 1) | 0 이면 길이 효과 없음, 1 이면 길이로 완전히 보정 | 0.75 |

교재는 매개변수 최적화를 하지 않을 때의 값이라고 전제하며, 개발용 테스트 컬렉션에서 조정하기를 권한다.

## 예시

질의 "retrieval rank" 에 대해 "retrieval" 이 10번 나오는 긴 문서와 3번 나오는 짧은 문서를 비교하면, k1 이 작을수록 두 문서의 단어 빈도 차이가 점수에 덜 반영되고, b 가 클수록 긴 문서의 점수가 더 깎인다.

## 에이전트 맥락

코드 식별자나 오류 메시지처럼 정확한 문자열이 중요한 검색에서 BM25 가 자주 쓰인다. [하이브리드 검색](../hybrid-search/README.md)에서 키워드 쪽 점수로 쓰이며, 이때 벡터 검색과 점수 체계가 달라 [순위 역수 융합](../reciprocal-rank-fusion/README.md)처럼 순위만 쓰는 방식이 자주 선택된다. 구체 제품별 사용은 조사하지 않았다(미확인).

## 흔한 오해

- **BM25 는 의미를 이해하지 않는다.** 단어 일치에 기반하므로 동의어나 바꿔 쓴 표현을 찾지 못한다.
- **TF-IDF 와 같은 식이 아니다.** 단어 빈도 포화와 길이 정규화가 명시적으로 들어 있다.
