# 순위 역수 융합 (Reciprocal Rank Fusion, RRF)

> 여러 검색 결과 목록에서 각 문서의 순위 역수 1/(k + 순위)를 더해 하나의 순위로 합치는 방법.

## 요약

- Cormack, Clarke, Buettcher 가 SIGIR 2009 에서 제안한 순위 융합 방법이다.
- 문서 d 의 점수는 모든 순위 목록에 대해 1/(k + r(d)) 를 합한 값이다. r(d) 는 해당 목록에서의 순위이다.
- 점수가 아닌 순위만 쓰므로 서로 점수 척도가 다른 검색기(예: [BM25](../bm25/README.md)와 벡터 유사도)를 보정 없이 합칠 수 있다.
- 논문은 k = 60 으로 고정했고, Elastic 의 rank_constant 기본값도 60 이다.

## 왜 필요한가

[하이브리드 검색](../hybrid-search/README.md)에서는 키워드 점수와 벡터 유사도의 척도가 달라 점수를 그대로 더할 수 없다. 점수를 정규화하는 방법도 있지만 분포에 민감하다. RRF 는 순위만 사용해 이 문제를 피한다. 논문 제목은 이 방법이 Condorcet 방식과 개별 순위 학습 방법을 능가한다고 주장한다.

## 어떻게 동작하나

식은 다음과 같다.

```
RRFscore(d) = Σ_{각 순위 목록 i} 1 / (k + r_i(d))
```

- r_i(d) 는 목록 i 에서 문서 d 의 순위(1 부터 시작)이다. 목록에 없는 문서는 그 목록에서 기여가 0 이다.
- 상수 k 는 상위 순위 문서와 하위 순위 문서의 격차를 완화한다. Elastic 문서는 값이 클수록 낮은 순위 문서의 영향이 커진다고 설명하며 최소값은 1 이다.
- 모든 목록의 가중치는 같다. Elastic 문서는 별도의 튜닝이 필요 없다고 설명한다.

## 예시

k = 60 일 때 문서 A 가 목록 1 에서 1위, 목록 2 에서 3위라면 점수는 1/61 + 1/63 이다. 목록 1 에서만 2위인 문서 B 의 점수는 1/62 이므로 A 가 B 보다 앞선다.

## 에이전트 맥락

[RAG](../rag/README.md) 검색 단계에서 BM25 와 벡터 검색 결과를 합칠 때 쓰인다. Azure AI Search 는 하이브리드 쿼리의 결과를 RRF 로 병합한다고 설명한다. 코딩 에이전트 제품별 채택은 조사하지 않았다(미확인).

## 흔한 오해

- **RRF 는 점수를 합치지 않는다.** 원 점수는 버리고 순위만 쓴다.
- **k = 60 이 이론적으로 도출된 값은 아니다.** 검색 요약에 따르면 논문은 예비 실험에서 k 를 60 으로 정한 뒤 바꾸지 않았다. 논문 PDF 본문은 이 조사에서 직접 읽지 못했다(미확인).
- **RRF 는 재순위화가 아니다.** 질의와 문서를 다시 채점하지 않고 기존 순위만 합친다. [재순위화](../reranker/README.md)와 구분한다.
