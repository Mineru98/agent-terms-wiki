> 사용자 제공 원문, 조회·검증 전. 출처 URL 없음. 등록일 2026-10-10.

\*\*스모크 테스트(Smoke Test)\*\*는 소프트웨어를 개발하거나 수정한 직후, 가장 기본적인 핵심 기능들이 정상적으로 동작하는지 빠르게 확인하는 테스트입니다.

쉽게 말하면, \*\*"일단 실행은 되고, 중요한 기능들이 망가지지는 않았지?"\*\*를 확인하는 과정입니다.

## 1. 예시로 이해하기

코딩 에이전트(Claude Code, Codex 등)에게 로그인 기능을 수정하라고 요청했다고 가정해 보겠습니다.

에이전트가 코드를 수정한 뒤 다음과 같이 테스트할 수 있습니다.

로그인 기능 스모크 테스트

4개 통과

서버가 정상적으로 실행되는가?

로그인 페이지가 열리는가?

정상적인 계정으로 로그인이 되는가?

로그인 후 대시보드에 접근할 수 있는가?

이 4가지가 통과했다고 해서 모든 버그가 없다는 뜻은 아닙니다. 핵심 흐름이 동작한다는 최소한의 신뢰를 확보한 것입니다.

반면 비밀번호를 100번 틀리는 경우, 세션 만료, 동시 로그인, SQL Injection 등 모든 예외 상황까지 확인하는 것은 일반적인 스모크 테스트의 범위를 넘어섭니다.

## 2. 다른 테스트와 무엇이 다를까?

| 테스트 종류               | 핵심 목적                  | 예시               |
| -------------------- | ---------------------- | ---------------- |
| 스모크 테스트              | 기본 기능이 살아 있는가?         | 로그인 → 대시보드 진입    |
| 단위 테스트 (Unit)        | 개별 함수가 정확한가?           | 비밀번호 검증 함수       |
| 통합 테스트 (Integration) | 구성 요소 간 연결이 정상인가?      | API ↔ DB 연동      |
| 회귀 테스트 (Regression)  | 수정으로 기존 기능이 망가지지 않았는가? | 로그인 수정 후 회원가입 확인 |
| E2E 테스트              | 실제 사용자 흐름이 정상인가?       | 가입 → 로그인 → 결제    |

여기서 중요한 점은 스모크 테스트는 테스트의 수준이나 도구가 아니라 테스트의 목적과 범위를 나타내는 용어라는 것입니다.

따라서 단위 테스트, API 테스트, E2E 테스트 중 일부를 골라 스모크 테스트로 구성할 수도 있습니다.

## 3. 코딩 에이전트에서는 어떻게 활용할까?

예를 들어 Next.js 프로젝트에서 코딩 에이전트가 기능을 구현한 뒤 다음과 같은 명령을 실행할 수 있습니다.

```
# 타입 검사
npx tsc --noEmit

# 프로덕션 빌드 확인
npm run build

# 서버 실행
npm run start

# HTTP 응답 확인 (별도 터미널)
curl -f http://localhost:3000
```

위의 빌드와 타입 검사는 실행 전 기본 검증이며, 서버 실행 및 HTTP 확인은 간단한 스모크 테스트에 해당합니다. 단, HTTP 200 응답만으로 로그인 등 실제 기능이 정상이라고 판단할 수는 없습니다.

실제 프로젝트에서는 Playwright 등을 사용해 핵심 사용자 흐름까지 검증하면 더욱 효과적입니다.

## 4. 코딩 에이전트에게 요청하는 방법

다음과 같이 지시하면 됩니다.

코드 수정이 완료되면 반드시 스모크 테스트를 수행하세요.

1. 프로젝트가 정상적으로 빌드되는지 확인합니다.
2. 애플리케이션을 실제로 실행합니다.
3. 변경된 기능의 핵심 정상 동작 경로(Happy Path)를 테스트합니다.
4. 기존의 주요 기능이 정상적으로 작동하는지 최소한으로 확인합니다.
5. 실패한 항목은 원인을 분석하고 수정한 뒤 재검증합니다.
6. 최종적으로 PASS / FAIL / NOT RUN 결과와 검증 근거를 보고합니다.

단순히 빌드가 성공했다는 이유로 스모크 테스트가 통과했다고 판단하지 마세요. 실행하지 않은 테스트를 통과했다고 보고해서도 안 됩니다.

## 5. 함께 알아두면 좋은 용어

코딩 에이전트에서 자주 같이 등장하는 개념입니다.

- Happy Path: 예외 없이 가장 정상적으로 동작하는 사용자 시나리오
- Sanity Test: 특정 수정사항이 의도대로 작동하는지 좁은 범위에서 확인하는 테스트
- Regression Test: 수정으로 인해 기존 기능에 문제가 생겼는지 확인하는 테스트
- Test Suite: 여러 테스트 케이스를 묶은 테스트 모음

핵심은 스모크 테스트가 모든 것을 검증하는 테스트가 아니라, 더 깊은 테스트를 진행할 가치가 있는 상태인지 빠르게 판단하는 1차 관문이라는 것입니다.

그래서 코딩 에이전트에게는 일반적으로 `코드 수정 → 빌드/정적 검사 → 스모크 테스트 → 상세 테스트 → 결과 보고` 순서로 검증하도록 지시하는 것이 좋습니다.
