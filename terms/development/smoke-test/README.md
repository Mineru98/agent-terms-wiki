# 스모크 테스트

> 소프트웨어를 개발하거나 수정한 직후, 가장 기본적인 핵심 기능이 정상적으로 동작하는지 빠르게 확인하는 테스트.

## 요약

- "일단 실행은 되고, 중요한 기능이 망가지지 않았는가"만 확인하는 1차 관문이다.
- 통과해도 버그가 없다는 뜻은 아니다. 더 깊은 테스트를 진행할 가치가 있는 상태라는 최소한의 신뢰만 확보한다.
- 단위·통합·E2E 같은 테스트 수준이나 도구가 아니라 테스트의 목적과 범위를 가리키는 용어다. 각 수준의 테스트 중 일부를 골라 구성할 수 있다.
- 예외 상황(비밀번호 100회 실패, 세션 만료, 동시 로그인, SQL Injection 등)까지 훑는 것은 일반적인 스모크 테스트의 범위를 넘는다.

## 왜 필요한가

코드를 수정한 뒤 상세 테스트를 모두 돌리면 시간이 오래 걸린다. 그런데 서버가 뜨지 않거나 핵심 화면이 열리지 않는 상태라면 상세 테스트는 의미가 없다. 스모크 테스트는 이런 치명적 실패를 먼저 걸러, 깊은 테스트로 넘어갈지 판단하게 해 준다.

## 어떻게 동작하나

변경과 관련된 핵심 정상 동작 경로(Happy Path)와 기존 주요 기능만 최소한으로 확인한다. 다른 테스트와의 차이는 아래와 같다.

| 테스트 종류 | 핵심 목적 | 예시 |
| --- | --- | --- |
| 스모크 테스트 | 기본 기능이 살아 있는가? | 로그인 → 대시보드 진입 |
| 단위 테스트(Unit) | 개별 함수가 정확한가? | 비밀번호 검증 함수 |
| 통합 테스트(Integration) | 구성 요소 간 연결이 정상인가? | API ↔ DB 연동 |
| 회귀 테스트(Regression) | 수정으로 기존 기능이 망가지지 않았는가? | 로그인 수정 후 회원가입 확인 |
| E2E 테스트 | 실제 사용자 흐름이 정상인가? | 가입 → 로그인 → 결제 |

코딩 에이전트에서의 일반적인 검증 순서는 다음과 같다.

`코드 수정 → 빌드/정적 검사 → 스모크 테스트 → 상세 테스트 → 결과 보고`

## 예시

로그인 기능을 수정한 뒤의 스모크 테스트는 다음 4가지를 확인한다.

1. 서버가 정상적으로 실행되는가?
2. 로그인 페이지가 열리는가?
3. 정상적인 계정으로 로그인이 되는가?
4. 로그인 후 대시보드에 접근할 수 있는가?

4개가 통과해도 모든 버그가 없다는 뜻은 아니다. 핵심 흐름이 동작한다는 확인일 뿐이다.

## 에이전트 맥락

Next.js 프로젝트에서 코딩 에이전트가 기능을 구현한 뒤 실행할 수 있는 명령 예시는 다음과 같다.

```bash
npx tsc --noEmit                 # 타입 검사
npm run build                    # 프로덕션 빌드 확인
npm run start                    # 서버 실행
curl -f http://localhost:3000    # HTTP 응답 확인 (별도 터미널)
```

타입 검사와 빌드는 실행 전 기본 검증이고, 서버 실행과 HTTP 확인이 간단한 스모크 테스트에 해당한다. HTTP 200 응답만으로 로그인 같은 실제 기능이 정상이라고 판단할 수는 없다. 핵심 사용자 흐름까지 확인하려면 Playwright 같은 브라우저 자동화 도구를 쓸 수 있다.

에이전트에게 스모크 테스트를 요구하는 지시문은 다음 항목을 포함하는 형태가 제안되었다.

1. 프로젝트가 정상적으로 빌드되는지 확인한다.
2. 애플리케이션을 실제로 실행한다.
3. 변경된 기능의 Happy Path 를 테스트한다.
4. 기존 주요 기능이 정상 작동하는지 최소한으로 확인한다.
5. 실패 항목은 원인을 분석하고 수정한 뒤 재검증한다.
6. 최종적으로 PASS / FAIL / NOT RUN 결과와 검증 근거를 보고한다.

빌드 성공만으로 스모크 테스트 통과를 판단하지 않는다. 실행하지 않은 테스트를 통과했다고 보고하지 않는다.

## 흔한 오해

- **빌드 성공 = 스모크 테스트 통과가 아니다.** 빌드·타입 검사는 실행 전 검증이고, 애플리케이션을 실제로 실행해 확인해야 스모크 테스트다.
- **스모크 테스트 통과 = 버그 없음이 아니다.** 예외 상황과 깊은 동작은 상세 테스트의 몫이다.
- **특정 도구나 테스트 수준이 아니다.** 목적과 범위를 가리키는 용어이므로 단위·API·E2E 테스트 어느 것으로도 구성할 수 있다.
- **Sanity Test 와 구분한다.** Sanity Test 는 특정 수정이 의도대로 작동하는지 좁은 범위에서 확인하는 테스트다. 스모크 테스트는 핵심 기능 전반이 살아 있는지를 본다. _(구분 기준은 사용자 제공 원문의 정의에 근거하며 별도 출처로 대조하지 않았다. 미확인)_

## 관련 용어

- [dry-run](../dry-run/README.md) — 실제로 실행하지 않고 결과를 미리 확인한다. 스모크 테스트는 반대로 실제로 실행해서 확인한다.
- [golden-set](../golden-set/README.md) — 에이전트 작업의 정답 판정 기준을 미리 갖춘 평가 모음. 스모크 테스트가 빠른 1차 확인이라면 이쪽은 정해진 기준으로 하는 평가다.
