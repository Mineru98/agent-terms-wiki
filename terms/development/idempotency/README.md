# 멱등성 (Idempotency)

> 같은 요청을 한 번 보내든 여러 번 보내든 서버에 남는 최종 효과가 같은 성질.

## 요약

- 멱등성은 "응답이 같다"가 아니라 "서버 상태에 미치는 의도된 효과가 같다"는 뜻이다. RFC 9110 은 이를 요청 메서드의 성질로 정의한다.
- HTTP 에서는 GET, HEAD, OPTIONS, TRACE(안전한 메서드), PUT, DELETE 가 멱등이고 POST 는 멱등이 아니다.
- 통신 실패로 응답을 못 받았을 때, 멱등한 요청은 자동으로 다시 보내도 안전하다.
- POST 같은 비멱등 요청을 안전하게 재시도하려면 클라이언트가 만든 멱등 키(idempotency key)를 요청에 실어 서버가 중복을 알아보게 한다.

## 왜 필요한가

네트워크에서는 요청이 서버에 도착해 처리됐는데 응답만 유실되는 일이 생긴다. 클라이언트는 처리 여부를 알 수 없어 재시도해야 하는데, 결제나 주문 생성처럼 재시도가 부작용을 두 번 일으키는 요청이면 이중 결제 같은 사고가 난다. 멱등성은 재시도를 안전하게 만들어 "최소 한 번 전달" 방식의 재시도를 허용한다.

## 어떻게 동작하나

### HTTP 메서드 관점

RFC 9110 은 멱등 메서드를 "같은 요청을 여러 번 보냈을 때 서버에 미치는 의도된 효과가 한 번 보냈을 때와 같은 메서드"로 정의한다. PUT, DELETE, 그리고 안전한 메서드가 이에 해당한다.

| 메서드 | 안전(safe) | 멱등 | 설명 |
| --- | --- | --- | --- |
| GET | 예 | 예 | 조회만 하므로 상태를 바꾸지 않는다 |
| PUT | 아니오 | 예 | 리소스를 지정한 내용으로 통째로 교체하므로 반복해도 결과가 같다 |
| DELETE | 아니오 | 예 | 첫 호출은 삭제하고 이후 호출은 이미 없는 상태를 유지한다 |
| POST | 아니오 | 아니오 | 호출마다 새 리소스를 만들 수 있다 |

멱등성은 서버 상태에 관한 성질이므로 응답 코드는 달라져도 된다. 예를 들어 DELETE 는 첫 호출에서 200 을, 이후 호출에서 404 를 줄 수 있어도 멱등이다. 다만 메서드가 멱등이라는 것은 규약이며, 서버가 규약대로 구현해야 실제로 성립한다.

### 멱등 키 패턴

1. 클라이언트가 요청마다 고유한 키(UUID 같은 무작위 값)를 만들어 `Idempotency-Key` 헤더에 담는다.
2. 서버는 처음 보는 키면 요청을 처리하고 결과(상태 코드와 본문)를 키와 함께 저장한다.
3. 같은 키가 다시 오면 처리하지 않고 저장해 둔 결과를 돌려준다.
4. 같은 키가 다른 내용의 요청에 쓰이면 오류로 거절한다.

IETF HTTPAPI 작업 그룹의 초안(draft-ietf-httpapi-idempotency-key-header)은 처리 중인 요청과 같은 키가 오면 409, 키가 다른 페이로드와 함께 재사용되면 422, 필수 헤더가 없으면 400 을 쓰도록 권고한다. 이 문서는 인터넷 초안이며 2026-04-18 에 만료된 것으로 표시되어 있어 표준이 아니다.

## 예시

```http
POST /v1/payments HTTP/1.1
Idempotency-Key: "8e03978e-40d5-43e8-bc93-6894a57f9324"
Content-Type: application/json

{"amount": 12000, "currency": "KRW"}
```

응답을 받지 못해 같은 키로 다시 보내면, 서버는 새 결제를 만들지 않고 첫 요청의 결과를 돌려준다.

Stripe API v1 은 첫 요청의 상태 코드와 본문을 저장해 같은 키의 재시도에 그대로 돌려주고, 키는 24시간 이상 지나면 제거될 수 있으며, 키는 최대 255자다. 파라미터가 원래 요청과 다르면 오류를 낸다. GET 과 DELETE 는 정의상 멱등이므로 키를 보내지 않는다.

## 에이전트 맥락

코딩 에이전트가 API 호출이나 마이그레이션, 배포 스크립트를 재시도할 때 같은 작업이 두 번 실행되어도 안전한지가 문제가 된다. 에이전트가 만드는 스크립트나 호출에 멱등성이 있으면 실패 후 재실행이 쉬워진다. 이는 일반적 설계 원칙이며, 특정 에이전트 도구의 동작은 조사하지 않아 미확인이다.

## 흔한 오해

- **멱등은 응답이 항상 같다는 뜻이 아니다.** 서버 상태의 효과가 같다는 뜻이며, DELETE 의 응답 코드는 달라질 수 있다.
- **멱등은 안전(safe)과 다르다.** PUT 과 DELETE 는 상태를 바꾸지만 멱등하다. 안전한 메서드는 모두 멱등이지만 그 반대는 성립하지 않는다.
- **POST 는 멱등하지 않다고 해서 재시도가 불가능한 것이 아니다.** 멱등 키로 서버가 중복을 걸러 주면 안전하게 재시도할 수 있다.
- **멱등 키는 서버가 만들어 주는 값이 아니다.** 클라이언트가 만들어 보낸다.
