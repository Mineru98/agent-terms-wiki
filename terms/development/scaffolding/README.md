# 스캐폴딩

> 소프트웨어 개발에서 프로젝트를 시작하는 데 필요한 기본 구조와 초기 코드를 자동으로 생성하는 작업.

## 요약

- 건축 현장의 비계(scaffold)에서 온 비유로, 본격적인 구현 전에 프로젝트의 뼈대를 세우는 작업이다.
- 결과물은 디렉터리, 설정 파일, 기본 컴포넌트·템플릿 등이며 실제 비즈니스 로직은 포함하지 않는 것이 일반적이다.
- 범위는 도구에 따라 다르다. 실행 가능한 예제 코드, 기본 테스트, CI 설정까지 생성하는 도구도 있다.
- 에이전트가 "스캐폴딩 완료"라고 보고해도 기능 구현이 끝났다는 뜻은 아니다.

## 왜 필요한가

새 프로젝트를 시작할 때마다 폴더 구조, 설정, 기본 파일을 손으로 만들면 반복 작업이 많고 프로젝트 사이 편차도 생긴다. 스캐폴딩으로 개발을 시작할 수 있는 상태를 먼저 갖추면, 개발자는 로그인 로직·데이터베이스 연동·사용자 인증 같은 실제 기능 구현에 집중할 수 있다.

## 어떻게 동작하나

스캐폴딩과 실제 구현은 목적과 결과가 다르다.

| 구분 | 스캐폴딩 | 실제 구현 |
| --- | --- | --- |
| 목적 | 개발 기반 마련 | 기능 완성 |
| 디렉터리 | 폴더 구조 생성 | 필요한 구조 확장 |
| 코드 | 기본 파일 및 템플릿 생성 | 실제 비즈니스 로직 작성 |
| 설정 | 패키지와 환경 설정 | 운영 환경에 맞게 조정 |
| 결과 | 개발 시작 가능한 상태 | 요구 기능이 동작하는 상태 |

## 예시

코딩 에이전트에 "Next.js와 TypeScript를 사용해서 로그인 기능이 있는 웹서비스를 만들어줘"라고 요청하면, 에이전트가 먼저 Next.js 프로젝트의 디렉터리, 설정 파일, 기본 컴포넌트를 생성한다. 이 단계가 스캐폴딩이다. 로그인 로직 등 실제 기능은 이후 구현 단계에서 작성한다.

## 에이전트 맥락

코딩 에이전트(Claude Code, Codex 등)가 자주 쓰는 표현은 다음과 같다.

| 표현 | 의미 |
| --- | --- |
| `Scaffold the project` | 프로젝트의 초기 구조를 만든다 |
| `Scaffold a REST API` | 엔드포인트, 라우터, 컨트롤러, 스키마 등 기본 코드를 생성한다. 데이터 처리 로직은 미완성일 수 있다 |
| `Scaffold the authentication module` | 인증 관련 폴더, 인터페이스, 미들웨어, 기본 함수를 만든다. 인증 시스템 전체 구현과는 다르다 |
| `Use the existing scaffold` | 이미 만들어진 기본 구조를 재사용한다 |

프롬프트에 따라 결과가 크게 달라진다.

- `Scaffold a KMS service` → KMS 서비스의 기본 구조와 인터페이스 생성
- `Implement a working KMS service` → 키 생성·암호화·복호화·권한 검증 등 실제 기능 구현

따라서 에이전트에 작업을 맡길 때는 Scaffold(구조 생성), Implement(기능 구현), Test(검증)를 구분하는 것이 좋다.

## 흔한 오해

- **"스캐폴딩 완료 = 기능 완료"**: 아니다. 기본 구조가 준비됐다는 뜻일 뿐이다.
- **보일러플레이트(boilerplate)와 동일하다**: 스캐폴딩은 기본 구조와 코드를 생성하는 작업·과정이고, 보일러플레이트는 여러 프로젝트에서 반복 사용하는 기본 코드나 템플릿이다. 예를 들어 `create-next-app`으로 프로젝트를 생성하는 행위는 스캐폴딩, 생성된 기본 설정과 템플릿 코드는 보일러플레이트로 볼 수 있다.

## 관련 용어

- 보일러플레이트(boilerplate) — 스캐폴딩이 만들어내는 반복 사용 코드·템플릿. _(아직 위키에 등록되지 않아 링크 없음)_
