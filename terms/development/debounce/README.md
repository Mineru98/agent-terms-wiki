# 디바운스 (Debounce)

> 같은 동작이 짧은 간격으로 반복될 때, 마지막 호출 뒤 지정한 시간이 지나도록 추가 호출이 없어야 비로소 한 번 실행하는 방식.

## 요약

- 디바운스(debounce)는 너무 가까이 붙어 일어나는 호출을 하나로 합치는 기법이다.
- 호출이 들어올 때마다 대기 시간이 처음부터 다시 시작된다. 호출이 멈추고 대기 시간이 지나야 실행된다.
- 실행 시점은 선행(leading)과 후행(trailing)으로 고를 수 있다. 일반적으로는 후행에서만 실행한다.
- 검색창 입력, 창 크기 변경처럼 입력이 멈춘 뒤의 결과만 필요한 곳에 쓴다.

## 왜 필요한가

사용자가 검색어를 입력하면 글자마다 입력 이벤트가 발생한다. 이벤트마다 서버에 요청을 보내면 중간 단계의 검색어에 대한 요청이 대부분 쓸모없어지고 서버와 화면에 부담이 된다. 디바운스는 입력이 잠시 멈춘 뒤에만 처리하도록 해 이런 낭비를 줄인다.

## 어떻게 동작하나

MDN 용어집은 디바운스를 "짧은 간격 안에 일어난 호출을 버리고 한 번의 호출로 합치는 것"으로 설명한다. 흐름은 다음과 같다.

1. 첫 호출 시점을 선행 지점(leading edge)이라 한다.
2. 이전 호출로부터 대기 시간 안에 들어온 호출은 같은 묶음에 속하고, 대기 시간은 다시 시작된다.
3. 마지막 호출 뒤 대기 시간이 지나면 후행 지점(trailing edge)에 도달한다.

| 옵션 | 동작 |
| --- | --- |
| trailing 만 사용 | 묶음의 마지막에 한 번 실행한다. 가장 흔한 형태다. |
| leading 만 사용 | 묶음의 첫 호출에서 즉시 실행하고, 대기 시간이 끝날 때까지 이후 호출은 무시한다. |
| 둘 다 사용 | 양쪽에서 실행할 수 있다. 같은 묶음 안에서 호출이 한 번뿐이면 후행 실행은 생략되는 구현이 있다. |

Lodash 의 `_.debounce(func, [wait=0], [options={}])` 는 `leading`(기본 false), `trailing`(기본 true), `maxWait`(함수 실행을 미룰 수 있는 최대 시간) 옵션을 제공한다. 양쪽을 모두 켜면 대기 시간 안에 디바운스된 함수가 두 번 이상 호출된 경우에만 후행에서 실행된다는 점은 Lodash 소스 주석(미러 사본)에서 확인했다.

## 예시

검색창에 입력을 멈추고 300ms 가 지나면 한 번만 검색하는 최소 코드다.

```js
function debounce(fn, wait) {
  let timer;
  return (...args) => {
    clearTimeout(timer);                       // 이전 대기를 취소한다
    timer = setTimeout(() => fn(...args), wait); // 대기를 새로 시작한다
  };
}

const search = debounce((query) => {
  console.log("검색:", query);
}, 300);

document.querySelector("#search").addEventListener("input", (e) => {
  search(e.target.value);
});
```

이 코드는 후행 실행만 구현한 것이다. 선행 실행과 취소(`cancel`), 즉시 실행(`flush`)이 필요하면 Lodash 같은 검증된 구현을 쓴다.

## 흔한 오해

- **디바운스와 쓰로틀링은 다르다.** 디바운스는 호출이 이어지는 동안에는 실행하지 않고 멈춘 뒤에 실행한다. 쓰로틀링(throttling)은 호출이 이어지는 동안에도 일정 간격마다 실행한다.
- **디바운스는 호출을 늦출 뿐 아니라 합친다.** 대기 중에 들어온 중간 호출은 실행되지 않고 버려진다.
- **호출이 끝없이 이어지면 실행되지 않을 수 있다.** 이를 막으려면 `maxWait` 같은 상한 옵션을 쓴다.
