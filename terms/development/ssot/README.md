# 단일 진실 원천 (Single Source of Truth)

> 같은 정보를 여러 곳에 따로 두지 않고, 각 정보를 한 곳에서만 정의하고 관리하며 나머지는 그곳을 참조하게 하는 설계 원칙.

## 요약

- SSOT(Single Source of Truth)는 특정 시스템이나 제품의 이름이 아니라, 데이터와 문서를 어디에서 소유하고 수정할지 정하는 원칙이다.
- 각 데이터 항목은 한 곳에서만 저장·수정하고, 다른 곳은 복사본이나 참조로 취급한다.
- 소스 코드, 설정, 문서, 데이터베이스 어디에나 적용할 수 있다.
- 모든 데이터를 하나의 물리적 저장소에 모으는 것과는 다르다. 항목별로 소유 시스템을 하나씩 정하는 방식도 SSOT 로 설명된다.

## 왜 필요한가

같은 값이 여러 곳에 복사되어 있으면 한쪽만 고쳐졌을 때 두 값이 어긋나고, 어느 쪽이 맞는지 판단할 기준이 사라진다. 팀마다 다른 수치로 의사결정을 하거나, 문서와 코드가 서로 다른 설정을 설명하는 문제가 여기서 나온다. SSOT 는 수정할 곳을 하나로 정해 이런 불일치의 원인을 줄인다.

## 어떻게 동작하나

1. 정보 항목마다 원천(source)을 하나 정한다. 예를 들어 직원 정보는 인사 시스템, 기기 정보는 기기 관리 도구, 접근 권한은 ID 공급자가 소유한다.
2. 다른 시스템과 문서는 원천에서 값을 읽거나 생성해서 쓴다. 복사본을 직접 고치지 않는다.
3. 원천과 복사본이 어긋나면 원천을 기준으로 복사본을 다시 맞춘다.
4. 원천을 바꾸는 절차(누가, 어떤 검토를 거쳐 수정하는가)를 함께 정한다. 이 거버넌스가 없으면 원천이 있어도 값이 흔들린다.

시스템 간 용어는 다음과 같이 구분되어 설명된다.

| 용어 | 의미 |
| --- | --- |
| 기록 시스템(system of record) | 한 업무 영역의 원본 데이터를 생성하고 유지하는 신뢰할 수 있는 시스템 |
| 진실 원천(source of truth) | 여러 기록 시스템의 데이터를 모아 하나의 완전한 시각을 제공하는 곳 |
| 단일 진실 원천(SSOT) | 진실 원천을 여럿 두지 않고 하나로 맞추려는 설계 목표 |

## 예시

설정 값 하나를 한 파일에서만 정의하고 나머지는 거기서 읽는 가장 작은 예다.

```ts
// config/limits.ts  (유일한 정의)
export const MAX_UPLOAD_MB = 20;

// api/upload.ts  (참조만 한다)
import { MAX_UPLOAD_MB } from "../config/limits";
if (file.sizeMb > MAX_UPLOAD_MB) throw new Error("too large");
```

프론트엔드 안내 문구에 "20MB" 를 직접 적어 두면 값이 두 곳에 생기므로, 같은 상수에서 문구를 만들어야 SSOT 가 유지된다.

## 에이전트 맥락

코딩 에이전트가 프로젝트의 규칙을 여러 문서(`CLAUDE.md`, README, 주석)에 중복해서 적으면 서로 모순되는 지시가 생길 수 있다. 규칙은 한 파일에 두고 다른 곳에서는 링크하는 식으로 SSOT 를 지키면 에이전트가 읽는 지시가 일관된다. 이 적용 방식은 조사한 출처가 직접 다루지 않은 실무 해석이므로 미확인 사항으로 본다.

## 흔한 오해

- **SSOT 는 모든 것을 한 시스템에 합치는 것이 아니다.** 항목마다 소유 시스템을 하나씩 정하는 거버넌스 규칙으로 보는 설명이 있다. 반면 중앙 저장소로 설명하는 자료도 있어 출처마다 해석이 갈린다.
- **정본(canonical source)과 같은 말이 아니다.** 정본은 "공식으로 인정된 하나의 판본이 무엇인가"를 가리키는 개념이고, SSOT 는 "그 값을 어디서만 정의하고 수정하는가"라는 구조 원칙이다. 정본이 지정되어도 복사본이 여기저기 수정되면 SSOT 는 깨진다. 다만 "정본"의 정의를 직접 다룬 출처는 찾지 못했으므로 이 구분은 미확인이다.
- **SSOT 는 도구를 설치해서 얻는 것이 아니다.** 데이터 거버넌스와 시스템 간 연동이 함께 있어야 유지된다.
- **복사본이 있으면 SSOT 가 아닌 것이 아니다.** 복사본이 원천에서 파생되고 직접 수정되지 않는다면 원칙을 지키고 있다.

## 관련 용어

- 비교·인접 용어 (순서 없음)
