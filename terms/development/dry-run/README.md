# Dry-run

> 작업을 실제로 실행하거나 시스템을 변경하지 않고, 실행했을 때 어떤 일이 일어날지 미리 확인하는 사전 모의 실행.

## 요약

- 파일 삭제·DB 변경·배포처럼 되돌리기 어려운 작업 전에 영향 범위만 먼저 보여 주는 방식이다.
- 코딩 에이전트에서는 "실제로 수정하지 말고, 무엇을 수정할지 먼저 보여줘"에 해당한다.
- 도구의 `--dry-run` 옵션(실제 실행 경로를 검증)과, 에이전트에게 계획만 쓰게 하는 프롬프트 방식(계획 작성만)은 구분해야 한다.
- 표준 기능이 아니라 도구마다 지원 범위가 다르며, "실행해도 안전하다"는 보증이 아니다.

## 왜 필요한가

삭제·마이그레이션·배포·인프라 변경은 한 번 실행하면 되돌리기 어렵거나 비용이 크다. Dry-run은 변경 대상과 부작용을 실행 전에 확인할 수 있게 해, 잘못된 범위의 작업을 사전에 걸러 낸다.

## 어떻게 동작하나

대상 시스템의 상태를 바꾸지 않고, 실행 예정인 작업(삭제 대상 목록, 실행할 SQL, 생성·수정·삭제될 리소스 등)만 출력한다.

| 상황 | Dry-run에서 확인하는 내용 |
| --- | --- |
| 코드 리팩터링 | 변경 대상 파일과 예상 수정 내용 |
| 데이터베이스 마이그레이션 | 실행 예정인 SQL과 스키마 변경 |
| 파일 정리 | 삭제·이동 대상 파일 목록 |
| API 배포 | 배포 대상과 예상 설정 변경 |
| 인프라 변경 | 생성·수정·삭제될 리소스 |
| 대규모 자동화 | 실행 단계와 예상 영향 범위 |

구현 수준은 도구마다 다르다. 실제 실행 경로를 검증하는 도구도 있고, 예상 작업 계획만 작성하는 에이전트도 있다.

## 예시

Git: 삭제될 추적되지 않는 파일·디렉터리만 보여 준다.

```bash
git clean -nd   # dry-run: 목록만 출력
git clean -fd   # 실제 삭제
```

Docker Compose (지원되는 버전에서):

```bash
docker compose --dry-run up -d
```

## 에이전트 맥락

자연어 지시를 받는 에이전트(Claude Code, Codex 등)에는 분석과 계획만 수행하도록 요청하는 방식으로 쓴다.

```text
먼저 Dry-run 모드로 작업을 수행하세요.
1. 현재 프로젝트를 분석하고 변경이 필요한 파일을 식별하세요.
2. 각 파일의 수정 예정 내용과 변경 이유를 설명하세요.
3. 파일 생성·수정·삭제, DB 변경, 외부 API 호출 등 예상되는 부작용을 나열하세요.
4. 실제 파일 수정, 명령 실행에 따른 상태 변경, 배포는 수행하지 마세요.
5. 예상 변경 사항과 검증 방법을 정리하세요.
현재 단계에서는 분석과 계획만 수행하고, 실제 변경은 별도의 승인 이후 진행하세요.
```

이 프롬프트는 계획만 수립하는 방식이며, 명령어의 `--dry-run` 옵션과는 다르다. 에이전트 도구별 지원 여부는 _(미확인)_.

## 흔한 오해

| 용어 | 의미 |
| --- | --- |
| Dry-run | 실제 변경 없이 실행 결과나 영향을 미리 확인 |
| Plan Mode | 작업 수행 전 구현 계획을 수립 |
| Sandbox | 격리된 환경에서 실제 코드를 실행 |
| Mock | 실제 API·DB 등의 동작을 가짜 구현으로 대체 |
| Rollback | 이미 적용한 변경을 이전 상태로 되돌림 |

- Sandbox 는 격리 환경 안에서 실제로 파일을 수정하거나 프로그램을 실행할 수 있다. Dry-run 은 대상 시스템의 상태 변경 방지에 초점을 둔다.
- Dry-run 은 "실행해도 안전하다"는 보증이 아니다. 중요한 DB 변경·배포는 Dry-run 이후에도 별도 검증이 필요하다.

## 관련 용어

- 비교·인접 용어 (순서 없음)
  - [smoke-test](../smoke-test/README.md) — Dry-run 은 실행하지 않고 영향을 미리 확인하고, 스모크 테스트는 실제로 실행해 핵심 기능이 동작하는지 확인한다.

Plan Mode, Sandbox, Mock, Rollback 은 미등록이라 링크하지 않았다.
