**Dry-run(드라이 런)**은 실제로 작업을 실행하거나 시스템을 변경하지 않고, 실행했을 때 어떤 일이 발생할지 미리 확인하는 사전 모의 실행을 의미합니다.

코딩 에이전트에서는 쉽게 말해 **"실제로 수정하지 말고, 무엇을 수정할지 먼저 보여줘"**라는 개념입니다.

## 1. 실제 실행과 Dry-run의 차이

예를 들어 코딩 에이전트에게 다음과 같이 요청했다고 가정하겠습니다.

> 프로젝트에서 사용하지 않는 파일을 모두 삭제해 줘.

일반 실행: 실제 파일 삭제 (old-config.json, unused.ts, temp.log → 파일 삭제됨)

Dry-run: 삭제 대상만 미리 확인 (old-config.json, unused.ts, temp.log → 파일 변경 없음)

즉, Dry-run에서는 삭제할 파일 목록을 출력하지만 실제 삭제는 하지 않습니다.

## 2. 코딩 에이전트에서 활용하는 경우

| 상황 | Dry-run에서 확인하는 내용 |
| --- | --- |
| 코드 리팩터링 | 변경 대상 파일과 예상 수정 내용 |
| 데이터베이스 마이그레이션 | 실행 예정인 SQL과 스키마 변경 |
| 파일 정리 | 삭제·이동 대상 파일 목록 |
| API 배포 | 배포 대상과 예상 설정 변경 |
| 인프라 변경 | 생성·수정·삭제될 리소스 |
| 대규모 자동화 | 실행 단계와 예상 영향 범위 |

단, Dry-run은 모든 도구에서 동일하게 구현되는 표준 기능이 아닙니다. 어떤 도구는 실제 실행 경로를 검증하지만, 어떤 코딩 에이전트는 단순히 예상 작업 계획만 작성합니다.

## 3. 실제 명령어 예시

### Git에서 Dry-run

```
git clean -nd
```

Git이 삭제할 추적되지 않는 파일과 디렉터리를 미리 보여주며, 실제 삭제는 하지 않습니다.

반면 다음 명령어는 실제 삭제합니다.

```
git clean -fd
```

### Docker Compose에서 Dry-run

```
docker compose --dry-run up -d
```

컨테이너와 네트워크 등에 대해 실행할 작업을 미리 보여줍니다. 지원되는 Docker Compose 버전에서 사용할 수 있습니다.

## 4. 코딩 에이전트에게 요청하는 방법

Claude Code나 Codex처럼 자연어 지시를 받는 에이전트에는 다음과 같이 요청할 수 있습니다.

먼저 Dry-run 모드로 작업을 수행하세요.

1. 현재 프로젝트를 분석하고 변경이 필요한 파일을 식별하세요.
2. 각 파일의 수정 예정 내용과 변경 이유를 설명하세요.
3. 파일 생성·수정·삭제, DB 변경, 외부 API 호출 등 예상되는 부작용을 나열하세요.
4. 실제 파일 수정, 명령 실행에 따른 상태 변경, 배포는 수행하지 마세요.
5. 예상 변경 사항과 검증 방법을 정리하세요.

현재 단계에서는 분석과 계획만 수행하고, 실제 변경은 별도의 승인 이후 진행하세요.

이 프롬프트는 에이전트에게 계획만 수립하는 방식의 Dry-run을 요청한 것입니다. 실제 명령어의 `--dry-run` 옵션을 사용하는 것과는 구분해야 합니다.

## 5. Dry-run과 자주 혼동하는 용어

| 용어 | 의미 |
| --- | --- |
| Dry-run | 실제 변경 없이 실행 결과나 영향을 미리 확인 |
| Plan Mode | 작업 수행 전 구현 계획을 수립 |
| Sandbox | 격리된 환경에서 실제 코드를 실행 |
| Mock | 실제 API·DB 등의 동작을 가짜 구현으로 대체 |
| Rollback | 이미 적용한 변경을 이전 상태로 되돌림 |

특히 Dry-run과 Sandbox는 다릅니다. Sandbox에서는 격리된 환경 안에서 실제 파일을 수정하거나 프로그램을 실행할 수 있지만, Dry-run은 원칙적으로 대상 시스템의 상태 변경을 방지하는 데 초점을 둡니다.

핵심은 Dry-run이 '실행해도 안전하다'는 보증이 아니라, '실제 변경 전에 영향을 확인하도록 설계된 실행 방식'이라는 점입니다. 도구마다 지원 범위가 다르므로 중요한 DB 변경이나 배포에서는 Dry-run 이후에도 별도 검증이 필요합니다.
