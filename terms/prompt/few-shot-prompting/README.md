# 퓨샷 프롬프팅 (Few-shot Prompting)

> 프롬프트 안에 입력과 기대 출력의 예시를 몇 개 넣어, 모델 가중치를 바꾸지 않고 작업 방식을 보여 주는 방식.

## 요약

- 예시(demonstration)를 프롬프트에 포함해 형식, 어조, 판단 기준을 전달한다.
- GPT-3 논문(Brown et al., 2020)이 이 방식을 컨텍스트 내 학습(in-context learning)으로 부르며 대규모로 평가했다.
- Anthropic 문서는 관련성, 다양성, 구조를 갖춘 예시를 3개에서 5개 넣으라고 권한다.
- 예시의 순서와 선택에 따라 결과가 크게 달라질 수 있다는 연구가 있다.

## 왜 필요한가

원하는 출력 형식이나 판단 기준은 말로 설명하기 어려울 때가 많다. 예시 한두 개가 긴 설명보다 의도를 정확히 전달하며, 별도 학습 없이 프롬프트만 바꿔 쓸 수 있다.

## 어떻게 동작하나

Brown et al. 은 작업 설명 뒤에 컨텍스트 윈도우에 들어가는 만큼의 시연(보통 10에서 100개)을 붙이고 마지막에 새 입력을 주는 조건을 few-shot 으로 정의했다. 모델은 이 텍스트만으로 작업을 수행하며 가중치는 갱신되지 않는다. 논문은 이 과정을 컨텍스트 내 학습이라고 부른다.

예시를 쓸 때의 지침은 다음과 같다.

| 항목 | Anthropic 문서의 안내 |
| --- | --- |
| 관련성 | 실제 사용 사례를 가깝게 반영한다 |
| 다양성 | 경계 사례를 포함하고, 의도하지 않은 패턴을 학습하지 않을 만큼 다르게 한다 |
| 구조 | `<example>` 태그로 감싸 지시와 구분한다 |
| 개수 | 3개에서 5개 |

OpenAI 문서도 다양한 입력과 원하는 출력을 보여 주라고 안내한다.

### 순서와 선택의 영향

- Lu et al.(2022)은 같은 예시라도 배열 순서에 따라 성능이 최고 수준에서 무작위 추측 수준까지 달라지며, 이 현상이 큰 모델에서도 나타난다고 보고했다. 한 모델에서 좋은 순서가 다른 모델에서도 좋다는 보장은 없었다.
- Min et al.(2022)은 분류와 객관식 작업에서 예시의 정답 레이블을 무작위로 바꿔도 성능이 거의 떨어지지 않았다고 보고했다. 레이블 공간, 입력 텍스트의 분포, 전체 형식이 더 중요하다는 해석이다. 이는 실험한 작업 범위의 결과이며 모든 작업에 일반화되지는 않는다.

## 예시

```text
리뷰의 감정을 분류하라.

리뷰: 화면이 선명하고 가볍다.
감정: 긍정

리뷰: 일주일 만에 고장 났다.
감정: 부정

리뷰: 배송은 빨랐지만 포장이 뜯겨 있었다.
감정:
```

## 에이전트 맥락

코딩 에이전트에 커밋 메시지 형식이나 테스트 작성 스타일을 맞추게 하려면 지침 파일이나 요청문에 실제 사례를 한두 개 넣는 방법이 쓰인다. 예시는 모델이 그대로 베끼는 경향이 있어, 다양성을 확보하지 않으면 모든 출력이 예시와 같은 모양이 될 수 있다. 이 문단은 일반적 사용 설명이며 별도 출처는 없다(기억 기반·미확인).

## 흔한 오해

- **예시가 많을수록 좋다는 오해.** 개수보다 관련성과 다양성이 강조되며, 컨텍스트 윈도우도 소모한다.
- **예시의 순서는 상관없다는 오해.** 순서에 민감하다는 연구가 있다.
- **in-context learning 이 모델을 학습시킨다는 오해.** 가중치는 바뀌지 않으며 그 대화의 입력으로서만 작용한다.
