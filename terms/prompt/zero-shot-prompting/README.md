# 제로샷 프롬프팅 (Zero-shot Prompting)

> 예시를 하나도 넣지 않고 작업을 설명하는 지시만으로 모델에 일을 시키는 방식.

## 요약

- 프롬프트에 입력과 기대 출력의 시연(demonstration)이 없고 지시만 있다.
- GPT-3 논문(Brown et al., 2020)은 시연 수에 따라 zero-shot, one-shot, few-shot 세 조건으로 평가를 나눴다.
- 가장 짧고 쓰기 쉽지만, 출력 형식이나 기준이 모호하면 결과가 흔들릴 수 있다.
- 결과가 불안정하면 예시를 추가하는 [퓨샷 프롬프팅](../few-shot-prompting/README.md)으로 넘어가는 것이 흔한 순서다.

## 왜 필요한가

예시를 만들려면 시간이 들고, 예시가 의도하지 않은 패턴을 모델에 심을 위험도 있다. 작업이 단순하거나 모델이 이미 작업을 잘 이해하는 경우에는 지시만으로 충분한 경우가 많다. 제로샷은 이런 경우의 기본 출발점이다.

## 어떻게 동작하나

Brown et al. 은 제로샷을 시연이 허용되지 않고 작업을 설명하는 자연어 지시만 주는 조건으로 정의했다. 한 개의 시연을 주는 조건이 one-shot, 컨텍스트 윈도우에 들어가는 만큼(논문은 보통 10에서 100개) 주는 조건이 few-shot 이다. 세 조건 모두 모델의 가중치를 갱신하지 않는다.

| 조건 | 프롬프트에 든 시연 수 |
| --- | --- |
| zero-shot | 0 |
| one-shot | 1 |
| few-shot | 여러 개 |

관련 연구로 Wei et al.(2021)은 지시 형태로 서술된 여러 작업에 미세조정(instruction tuning)한 모델 FLAN 이 보지 못한 작업에서 제로샷 성능이 크게 오른다고 보고했다. 즉 제로샷 성능은 프롬프트 기법만이 아니라 모델이 어떻게 학습됐는지에도 달려 있다.

## 예시

```text
다음 리뷰의 감정을 긍정, 부정, 중립 중 하나로만 답하라.

리뷰: 배송은 빨랐지만 포장이 뜯겨 있었다.
```

## 에이전트 맥락

코딩 에이전트에 "이 테스트가 실패하는 이유를 찾아 고쳐라"처럼 예시 없이 요청하는 일상적인 사용이 대부분 제로샷이다. 형식을 엄격히 맞춰야 하는 자동화에서는 지시문에 형식을 명시하거나 예시를 추가한다.

## 흔한 오해

- **제로샷은 프롬프트를 대충 쓴다는 뜻이 아니다.** 예시가 없을 뿐 지시의 명확성은 오히려 더 중요하다.
- **"zero-shot" 이라는 말은 문맥마다 다르게 쓰인다.** 논문은 제로샷이 모호한 용어일 수 있다고 직접 언급한다. 경사 갱신이 없다는 뜻으로 쓰이기도 하고, 시연 없이 지시만 준다는 뜻으로도 쓰인다. 이 문서는 후자의 뜻이다.
