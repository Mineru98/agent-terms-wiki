# 사고 연쇄 (Chain-of-Thought, CoT)

> 언어 모델이 최종 답을 내기 전에 중간 추론 단계를 문장으로 먼저 쓰게 하여, 여러 단계가 필요한 문제의 정확도를 높이는 프롬프트 방식.

## 요약

- 사고 연쇄는 답에 이르는 중간 추론 단계(intermediate reasoning steps)를 모델이 출력하도록 유도하는 방식이다.
- 원 논문(Wei et al., 2022)은 추론 과정이 포함된 예시 몇 개를 프롬프트에 넣는 방식(few-shot)으로 제안했다.
- 산술, 상식, 기호 추론 과제에서 정확도가 올랐고, 이 효과는 충분히 큰 모델에서 나타난다고 보고되었다.
- 예시 없이 "단계별로 생각해 보자(Let's think step by step)" 같은 한 문장만 붙여도 효과가 있다는 후속 연구(Kojima et al., 2022)가 있다.
- 추론 모델이 내부에서 쓰는 사고(thinking)와 프롬프트로 유도하는 사고 연쇄는 같은 개념이 아니다. 자세한 차이는 "흔한 오해"에 있다.

## 왜 필요한가

모델에게 질문만 하고 곧바로 답을 요구하면, 여러 단계의 계산이나 논리가 필요한 문제에서 중간 과정이 생략되어 틀리기 쉽다. 사람이 풀이 과정을 적으며 푸는 것처럼 모델도 중간 단계를 글로 쓰게 하면 각 단계가 다음 단계의 입력이 되어 최종 답에 이르기 쉬워진다. 원 논문은 이 방식으로 수학 단어 문제 벤치마크 GSM8K 에서 당시 최고 수준의 정확도를 얻었다고 보고했다.

## 어떻게 동작하나

1. 프롬프트에 "문제, 풀이 과정, 답" 형태의 예시를 몇 개 넣는다(few-shot CoT). 또는 지시문에 단계별로 생각하라는 문장을 넣는다(zero-shot CoT).
2. 모델은 새 문제에 대해서도 풀이 과정을 먼저 쓰고 마지막에 답을 쓴다.
3. 호출하는 쪽은 출력에서 최종 답만 추출하거나, 풀이 과정을 검토에 활용한다.

| 구분 | 프롬프트에 넣는 것 | 비고 |
| --- | --- | --- |
| Few-shot CoT | 추론 과정이 포함된 예시 여러 개 | Wei et al., 2022 |
| Zero-shot CoT | "Let's think step by step" 같은 지시 한 문장 | Kojima et al., 2022. 답 추출을 위해 2단계 프롬프트를 쓴다 |

## 예시

```text
질문: 카페에 손님이 23명 있었다. 11명이 나가고 6명이 들어왔다. 지금 몇 명인가?
풀이: 처음 23명에서 11명이 나가면 12명이다. 6명이 들어오면 18명이다.
답: 18명

질문: 상자에 사과가 15개 있었다. 7개를 꺼내고 4개를 더 넣었다. 지금 몇 개인가?
풀이:
```

첫 질문은 풀이 과정이 있는 예시이고, 두 번째 질문에서 모델이 같은 형식으로 풀이를 이어 쓰도록 유도한다.

## 에이전트 맥락

코딩 에이전트에게 복잡한 작업을 맡길 때 "먼저 계획을 쓰고, 그다음 수정하라"는 지시는 사고 연쇄를 프롬프트로 유도하는 사례로 볼 수 있다. 다만 에이전트 제품 문서에서 이 지시가 어떤 효과를 내는지는 이 조사에서 확인하지 못했다(미확인). 추론 모델을 쓰는 경우에는 사고 깊이를 프롬프트 문장이 아니라 설정값으로 조절하는 경로가 공식 문서에 있다. [추론 강도](../reasoning-effort/README.md)를 참고한다.

## 흔한 오해

- **사고 연쇄는 추론 모델의 내부 사고와 같지 않다.** 사고 연쇄는 프롬프트로 모델이 보이는 답변 안에 풀이를 쓰게 하는 기법이다. 추론 모델(reasoning model)은 답하기 전에 모델이 별도의 사고 토큰을 생성하도록 제품이 지원하는 방식이다. Anthropic 문서는 사고 토큰이 출력 토큰으로 과금되고 `max_tokens` 에 포함되며, 응답에는 요약된 사고가 반환될 수 있다고 설명한다. OpenAI 문서는 추론 토큰이 API 로 노출되지 않고 컨텍스트를 차지하며 출력 토큰으로 과금된다고 설명한다. 반면 프롬프트로 유도한 풀이는 평범한 출력 텍스트다.
- **추론 모델에 "단계별로 생각하라"를 덧붙여야 하는 것은 아니다.** OpenAI 추론 가이드는 추론 모델에 명확한 목표, 강한 제약, 출력 형식을 주고 중간 단계를 일일이 지시하지 말라는 취지로 안내한다. 이 안내를 모든 모델에 일반화할 수는 없으며, 모델별 권고는 해당 공식 문서로 확인해야 한다.
- **풀이 과정이 모델의 실제 계산 과정과 일치한다고 단정할 수 없다.** 이 점은 이번 조사에서 별도 출처로 확인하지 않았으므로 미확인이다.

## 관련 용어

- 비교·인접 용어 (순서 없음)
  - [추론 강도](../reasoning-effort/README.md): 추론 모델이 쓰는 사고 토큰의 양을 설정으로 조절한다. 프롬프트 문장으로 사고를 유도하는 사고 연쇄와 대비된다.

zero-shot, few-shot 프롬프팅 항목은 별도 작업에서 만들어지므로 여기서는 링크하지 않았다.
