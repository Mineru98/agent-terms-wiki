# 역할 프롬프팅 (Role Prompting)

> 프롬프트에서 모델에 "숙련된 코드 리뷰어" 같은 역할이나 페르소나(persona)를 지정해 응답의 관점과 어조를 유도하는 방식.

## 요약

- 보통 시스템 프롬프트에 한 문장으로 역할을 적는다.
- Anthropic 문서는 역할 지정이 행동과 어조를 집중시키며 한 문장만으로도 차이를 만든다고 안내한다.
- 반면 Zheng et al.(2024)은 4개 모델 계열과 사실 문제 2,410개로 실험해, 시스템 프롬프트의 페르소나가 성능을 높이지 않는다고 보고했다.
- 따라서 어조와 관점 조정에는 쓰일 수 있어도, 정확도를 높이는 수단이라는 근거는 약하다.

## 왜 필요한가

같은 질문에도 독자가 초보자인지 전문가인지, 응답이 요약인지 비평인지에 따라 알맞은 답이 다르다. 역할은 이런 배경을 짧게 전달하는 방법으로 쓰인다.

## 어떻게 동작하나

역할 문장을 지시문 앞부분이나 시스템 프롬프트에 넣는다. 모델은 이를 맥락으로 읽고 어휘, 상세 수준, 관점을 맞춘다. Anthropic 문서는 이를 행동과 어조의 집중으로 설명한다. 작동 원리에 대한 공식적인 기계적 설명은 확인하지 못했다.

## 예시

```text
당신은 보안 관점에서 코드를 검토하는 시니어 리뷰어다.
아래 diff 에서 입력 검증이 빠진 곳을 찾아 위치와 이유를 적어라.
```

## 에이전트 맥락

코딩 에이전트의 하위 에이전트(subagent)나 지침 파일에는 "리뷰어", "테스트 작성자" 같은 역할 이름이 자주 붙는다. 이 경우 역할은 정확도 향상보다 작업 범위와 보고 형식을 구분하는 표지로 쓰이는 면이 크다. 이 해석은 기억 기반이며 미확인이다.

## 흔한 오해

- **역할을 주면 정확도가 오른다는 오해.** Zheng et al. 의 실험에서는 페르소나를 넣은 경우가 넣지 않은 대조군보다 낫지 않았다. 페르소나의 성별, 유형, 분야에 따라 정확도가 달라지기는 했지만, 질문별로 최선의 페르소나를 자동으로 고르는 예측은 무작위 선택보다 나을 것이 없을 때가 많았다. 즉 효과는 대체로 예측하기 어렵다.
- **근거가 약하다는 것이 효과가 없다는 뜻은 아니다.** 해당 실험은 사실형 질문의 정확도를 측정했다. 어조, 형식, 창작처럼 다른 목적에서의 효과는 이 결과로 판단할 수 없다. Anthropic 의 안내와 이 연구는 서로 다른 지표를 본 것으로 보이나, 충돌 여부는 확정하지 못했다.
- **역할이 지식을 추가해 주지는 않는다.** 모델이 가진 능력 밖의 전문성을 이름만으로 얻을 수 없다.
